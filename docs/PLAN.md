# CyberLooter — план реализации

Мод доступности для Cyberpunk 2077: сбор всего лута в радиусе вокруг персонажа
по удержанию одной клавиши.

## Требования (согласованы с заказчиком)

1. Сбор срабатывает по **удержанию** клавиши (по умолчанию F), а не по одиночному нажатию.
   Удержание короткое (порог ~0.35 с), после срабатывания клавишу можно сразу отпустить —
   долго держать не нужно, сбор одноразовый.
2. Срабатывает, только если в этот момент **нет активного ванильного действия** на F.
   Смотришь на дверь или труп — F работает как обычно, мы молчим.
3. Радиус настраивается, по умолчанию **5 метров**.
4. **Индикатор** появляется на экране только тогда, когда в радиусе реально есть что
   подбирать: миниатюрная клавиша с цифрой рядом (`[F] 7`). Нет лута — виджета нет вовсе.
   При удержании рамка клавиши заполняется, отдельной шкалы прогресса нет.
5. Подбираем **всё**, что игра в принципе позволяет поднять, включая хлам и сломанное оружие.
   Единственное исключение — квестовые предметы (отключаемо в настройках).
6. Подбор — **штатным механизмом игры**, а не сырым переносом предметов.
7. **Минимум зависимостей.** Только Cyber Engine Tweaks, ничего больше.

## Зависимости

Ровно одна: **Cyber Engine Tweaks** (актуальный релиз v1.37.1).

Не используем и не требуем: redscript, RED4ext, ArchiveXL, TweakXL, Codeware, Mod Settings,
Native Settings UI. Настройки — собственное окно ImGui и свой `config.json`, ровно как
это делает BetterLootMarkers. Установка мода = распаковать одну папку.

## Как это будет работать

```
Игрок зажимает F
   │
   ├─ есть активная ванильная интеракция?  ──да──> ничего не делаем, F работает как обычно
   │  (UIInteractions.InteractionChoiceHub.choices не пуст)
   │
   ├─ удержание достигло порога (0.35 с)?  ──нет─> ждём / сброс по отпусканию
   │
   ▼
Сканируем радиус (5 м) ──> список объектов с лутом
   │
   ├─ фильтр: пустые, квестовые (если включено), не-лутабельные
   │
   ▼
Для каждого объекта: TransactionSystem:TransferAllItems(объект, игрок)
   │
   ▼
Игра сама: гасит маркер, снимает подсветку, убирает из HUD
```

Индикатор рисуется независимо: раз в ~0.3 с фоновое сканирование радиуса, и если найдено
хоть что-то — на экране появляется плашка «N объектов рядом», при удержании клавиши она
превращается в шкалу прогресса.

Обоснование каждого технического решения — в [RESEARCH.md](RESEARCH.md).

## Модули

### Config.lua

| Настройка | По умолчанию | Диапазон |
|---|---|---|
| `radius` | 5.0 м | 2–25 |
| `holdTime` | 0.35 с | 0.1–1.5 |
| `skipQuestItems` | вкл | — |
| `showIndicator` | вкл | — |
| `indicatorOffsetX` | 0 px | −800…800 |
| `indicatorOffsetY` | 60 px | −600…600 |
| `respectInteraction` | вкл | — |
| `maxObjectsPerSweep` | 24 | 4–100 |
| `debugLog` | выкл | — |

Окно ImGui открывается по оверлею CET, сохранение в `config.json` при закрытии.

### Input.lua

`registerInput("cyberlooter_sweep", "CyberLooter: собрать лут вокруг", cb(isDown))`.
На `isDown=true` запоминаем момент, на каждом `onUpdate` считаем длительность, при
достижении `holdTime` — один вызов сбора и блокировка повторов до отпускания.
Через `IsBound()` показываем предупреждение, если клавиша ещё не назначена.

### Scanner.lua

Три стратегии, пробуем по порядку, первая успешная запоминается на сессию:

1. `TargetingSystem:GetTargetParts` с `TargetSearchQuery` (`maxDistance` = радиус,
   `testedSet = TargetingSet.Complete`);
2. `MappinSystem:GetMappins(...)`;
3. пассивный реестр из перехвата `GameplayMappinController` (подход BetterLootMarkers).

Фильтрация кандидатов: `gameLootBag`, `gameItemDropObject`, `gameContainerObjectBase`,
`ScriptedPuppet` в состоянии «мёртв/без сознания». Отбрасываем всё, у чего
`GetTotalItemQuantity() <= 0`. Проверка дистанции — `Vector4.Distance` до игрока.

Результат кешируется на 0.3 с, чтобы индикатор не сканировал мир каждый кадр.

### Looter.lua

Для каждого объекта: проверка квестового флага (`IsQuest()`), затем
`TransactionSystem:TransferAllItems(obj, player)`. Если основной путь не сработал —
откат на поштучный `GetItemList` + `TransferItem`, факт отката пишется в лог.
Не больше `maxObjectsPerSweep` объектов за проход; всё в `pcall`.

### Hud.lua

`registerForEvent("onDraw")`, работает при закрытом оверлее (проверено, см. RESEARCH §8).
Окно без рамки, без фона и без обработки ввода (`NoInputs | NoDecoration | NoFocusOnAppearing`).

Содержимое — минимальное: прямоугольник с буквой назначенной клавиши и цифра рядом.

```
[F] 7
```

- **Буква** берётся из `GetBind("cyberlooter_sweep")`, а не хардкодится. Если клавиша не
  назначена — вместо цифры короткая подсказка, что бинд нужно задать в CET → Bindings.
- **Цифра** — количество позиций (стеков) в радиусе, а не штук. Стек из 45 патронов
  считается за единицу, иначе цифра станет трёхзначной и бесполезной.
- **Прогресс удержания** — заливка рамки вокруг буквы от 0 до 1 за `holdTime`.

Виджет полностью скрыт, если: в радиусе ничего нет; активна ванильная интеракция (иначе
индикатор обещает сбор, который не произойдёт); открыто меню, фотомод или диалог.

Позиция — под прицелом по центру экрана, смещение по X и Y настраивается.

### Log.lua

Пишет в `cyberlooter.log` рядом с модом: какая стратегия сканирования сработала, сколько
объектов найдено и обработано, какие вызовы упали и с какой ошибкой. По умолчанию выключен,
включается галочкой. Этот файл — наш основной канал обратной связи вместо отладки в игре.

## Этапы

| Этап | Содержание | Результат |
|---|---|---|
| 1 | Каркас: init, Config, Log, окно настроек | Мод грузится, окно открывается |
| 2 | Scanner с тремя стратегиями | Лог показывает, что находится в радиусе |
| 3 | Input + Looter | Сбор работает |
| 4 | Hud | Индикатор удержания |
| 5 | README, version.txt, публикация в приватный репозиторий | Готово к установке |

Этапы 1–5 пишутся за один заход, до первой выкатки. Дальше — итерации по логам.

## Условия проверки

Проверять будет заказчик на Windows (Steam-версия). Разработка идёт на Linux, запустить игру
здесь нельзя. Поэтому:

- каждый неоднозначный вызов обёрнут в `pcall` с записью в лог;
- у каждой критичной операции есть запасной путь;
- первая выкатка должна дать максимум информации даже в случае полного провала.

Реалистичный прогноз: 2–3 круга «выкатка → лог → правка» до стабильной работы.
